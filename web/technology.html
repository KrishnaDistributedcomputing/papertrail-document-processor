Technology reference

How Papertrail reads a PDF.

A local, inspectable pipeline accepts document batches, chooses native extraction or OCR page by page, and uses a Docker-hosted model to generate grounded insights.

Request path

Each document, five controlled stages

01Browser + Nginx

Accepts up to 10 PDFs and proxies same-origin API requests.

02FastAPI

Validates limits, stores the source, and creates a job.

03Redis

Queues active work while SQLite retains every run and result.

04Celery worker

Runs PyMuPDF, Tesseract OCR, classification, and Ollama analysis.

05Versioned JSON

Persists text, blocks, coordinates, provenance, and warnings.

Processing decisions

The worker keeps every decision visible

01

Native text first

PyMuPDF reads ordered spans, font sizes, page geometry, and coordinates. Pages with at least 30 usable characters remain native.

02

OCR only when needed

Low-text pages render at 300 DPI and pass through the local Tesseract English model. The result records ocr as its source.

03

Transparent classification

Weighted phrase rules use the filename, metadata, and extracted text. JSON includes the category, method, and matched terms.

04

Grounded local analysis

One or two selected local models receive the same bounded text and return comparable structured results.

Runtime boundaries

Local data, isolated services

Documents never leave the Docker project. The worker, Redis, and Ollama runtime use an internal network, while named volumes retain documents, SQLite history, results, queue data, and the model.
